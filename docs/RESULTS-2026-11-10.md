# lwrap — bwrap の Link 理論版（S関数ビルダー生成）RESULTS（2026-11-10）

**生成 ELF「lwrap」のサイズ: 13,968 バイト**（静的リンク、インタプリタなし、-nostdlib、raw syscall のみ）
比較: bwrap 72,160 バイト / proot 183,464 バイト。

## 設計：極宣言 → 生成されるエッジ列

MATLAB の S-Function Builder が「ブロックのインターフェース宣言＋処理」から
Simulink 接続用のラッパー（S関数）を生成するのと同型に、ここでは
**極（pole）の宣言**から **エッジ（接続の糊＝名前つき syscall ステップ列）** を
`sf_builder.py` が生成し、静的 ELF をビルドする。lwrap の C は手書きではない。

- 極の宣言（`spec_lwrap.json`）: 名前 lwrap、入力（argv の CLI・fd 0/1/2 引継ぎ・
  env は引き継がず最小 env を生成）、出力（コマンドの stdout／終了コードの伝播）、
  パラメータ（rootfs、uid/gid=0、workdir、proc/pid の任意段スイッチ）、状態列。
- ビルダー（`sf_builder.py`）: エッジカタログと位相順序を持ち、仕様を検証してから
  C を生成する。検証の実測：エッジ逆順の仕様は "edges are not in phase order" で拒否、
  bind_rootfs を欠いた仕様は "mount_proc requires bind_rootfs before it" で拒否（rc=1）。

| # | エッジ（名前） | 生成される syscall／処理 | 備考 |
|---|---|---|---|
| 1 | unshare_user | pipe2 ×2、fork、子が unshare(CLONE_NEWUSER)、親と同期 | 下記「失敗形1」のため親子分担形で生成 |
| 2 | deny_setgroups | 親が /proc/<子>/setgroups へ "deny" | 1 の中で親が実行 |
| 3 | write_uid_map | 親が /proc/<子>/uid_map へ "0 <外uid> 1" | 同上。部屋内 uid=0 |
| 4 | write_gid_map | 親が /proc/<子>/gid_map へ同型 | 同上 |
| 5 | unshare_mount | unshare(CLONE_NEWNS) | |
| 6 | unshare_pid | unshare(CLONE_NEWPID)＋fork、親は wait し終了コード伝播 | 任意段（--pid） |
| 7 | mount_private_root | mount(none, /, MS_REC\|MS_PRIVATE) | 伝播漏れ止め |
| 8 | bind_rootfs | mount(rootfs, rootfs, MS_BIND\|MS_REC) | |
| 9 | mount_proc | mount(proc, rootfs/proc) | 任意段（--proc）。このセルでは失敗が正（失敗形2） |
| 10 | chroot_rootfs | chroot(rootfs) | |
| 11 | chdir_work | chdir(workdir) | |
| 12 | exec_cmd | execve（/bin・/usr/bin 等を探索、最小 env） | 極のアルゴリズム本体 |

失敗したエッジは名前つきで落ちる：`lwrap: edge <名前> failed (errno=N)`、終了コード 111。

## ビルド手順
```
cd ~/workspace/experiments/lwrap
python3 sf_builder.py spec_lwrap.json --outdir .
# -> lwrap_gen.c (9,983 バイトの生成 C) を経て gcc -nostdlib -static -Os で lwrap を生成
./lwrap --root <rootfs> [--proc] [--pid] [--workdir DIR] -- CMD...
```

## 検証（較正3点＋実験脚本 C 腕、n=20）

実験は `exp/run_exp.py`（ベースライン脚本に C 腕を追加）に合流。
数値は `exp/results_lwrap.json`、要約は `exp/RESULTS_lwrap.md`。
対象は elfroom rootfs のコピー、`room_test.sh` 再生、proc なし形（制約のため）。

| 腕 | 中央値 | p95 | 出力（20回とも） | rc |
|---|---|---|---|---|
| A chroot | 0.0500 s | 0.0593 s | "800 / ROOM PASS" | 0 |
| B bwrap | 0.0622 s | 0.0765 s | "800 / ROOM PASS" | 0 |
| C lwrap | 0.0483 s | 0.0586 s | "800 / ROOM PASS" | 0 |

- 既知解（部屋様式の再生）: C は記録済みチェック room_test.sh で ROOM PASS、
  出力は A・B と完全一致（全腕 distinct_outputs=1、diff 0）。
- 負コン: C の部屋内で uid=0、ホスト側だけの目印ファイル /host_marker_lwrap_exp は不可視。
- 独立経路: B（bwrap）と同じ入力で出力 diff 0（上の表）。
- 隔離プローブ M4（C）: 3/3（uid=0／目印不可視／新 pid 空間でシェル PID=1。B は PID=2）。

### 予測の判定（exp/PREDICTION.md、測定前に固定したものに対して）
- P1（出力は全腕一致）: **的中**。
- P3（lwrap ≤ 20,000 バイト）: **的中**（13,968 バイト）。
- P4（起動中央値が bwrap の 0.8〜1.5 倍）: **不的中（速い側に下限割れ）**。
  同一セッション比 C/B = 0.0483/0.0622 = **0.78 倍**。範囲の下限 0.8 をわずかに下回った。
  なおベースライン測定回（2026-11-09）の B 中央値 0.0517 s と比べると 0.93 倍で範囲内だが、
  判定は同一セッション測定で行うのが筋なので、不的中として記録する。
  解釈：名前空間生成のコストは bwrap と同等でも、bwrap の汎用処理（多数のオプション解釈・
  /dev 構築など）を lwrap が持たない分だけ速い、という方向の外れ。
- P5（隔離プローブ 3/3）: **的中**（pid 段を含む形で 3/3）。

## 失敗形（名前つきで残す。回避でごまかさない）
1. **uid_map の自己書込みが EPERM**（このセルの制約、実測）：
   初版は子自身が /proc/self/uid_map を書く形で生成し、`edge write_uid_map failed (errno=1)`。
   util-linux の `unshare -U` でも setgroups/uid_map への書込みが Permission denied になることを
   独立に確認した。対策は bwrap と同型の「親が子の map を書く」分担形にビルダーを変更
   （エッジ 2〜4 は親側ヘルパとして生成され、unshare_user の中で仕様順に実行される）。
2. **新しい proc のマウントが EPERM**（このセルの制約、bwrap でも同じ）：
   `--proc` を付けると `lwrap: edge mount_proc failed (errno=1)`、終了コード 111。
   bwrap の "Can't mount proc on /newroot/proc: Operation not permitted" と同じ制約。
   したがって proc 段は仕様上の任意段に留め、検証は proc なしで通した。
   帰結：部屋の中では /proc が空（rootfs 付属の空ディレクトリ）で、ps 等は使えない。
3. **存在しない rootfs**: `lwrap: edge bind_rootfs failed (errno=2)`（ENOENT）、終了コード 111。
4. 開発中の自前バグ（記録として残す）：同期パイプの fd 配列を i64 で宣言したため
   pipe2 が書く 32-bit fd の並びと合わず ready[1] が 0 になり、親子が互いに待ち合う
   デッドロックになった。strace で `write(0, "r", 1) = EBADF` を観測して特定、int 配列に修正。

## 残り・境界
- env は引き継がず生成した最小 env（PATH/HOME/TERM）のみ。bwrap（env 引継ぎ）との差はここ。
- /dev は作らない（部屋様式のチェックは /dev を要しなかった。必要になればエッジ追加で対応）。
- pivot_root ではなく chroot を使用（仕様の選択肢のうち通った側）。
- 対象 rootfs は x86_64 のみ（生成 C は __x86_64__ ガード付き）。
